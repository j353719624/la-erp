# 独立 Go 后端恢复工程

此目录已经能独立编译和运行，不调用原安装包中的 ELF。它根据原程序数据库、IDA 伪代码、前端请求及隔离运行结果重新构建。当前版本还没有覆盖完整 ERP，不能直接替换生产系统。

## 本地运行

安装 Go 1.27.1，在本目录执行：

```sh
go mod download
go test ./...
go build -o la-erp-server ./cmd/la-erp-server
./la-erp-server -dev -listen 127.0.0.1:18887 -db data/recovered.db
```

Windows 构建和启动：

```powershell
go build -o la-erp-server.exe ./cmd/la-erp-server
.\la-erp-server.exe -dev -listen 127.0.0.1:18887 -db data/recovered.db
```

空数据库创建原版本的 162 张表和演示基础资料。初始账号 `admin`，密码 `admin123`；可用环境变量 `ERP_ADMIN_PASSWORD` 指定初始密码。已有用户时不重复导入演示数据。JWT 密钥首次随机生成并保存在数据库旁的 `.jwt.secret` 文件，重启后继续使用。开发模式只允许监听回环地址。

仓库根目录可执行 `node tests/recovered-server-smoke.mjs backend/la-erp-server` 验证真实进程。在 Windows 将末尾路径改成 `backend/la-erp-server.exe`。

前端开发代理连接新后端：

```powershell
cd ..\frontend
$env:ERP_BACKEND_URL = 'http://127.0.0.1:18887'
npm run dev
```

上述业务写入暂限超级管理员。单据编号使用原实测默认格式 `STIN/STOUT/SO/PO/SR/PRN/AR/AP/RC/PY/VOU/TR/ADJ/IC + 上海日期 + 四位流水号`，流水号和单据写入在同一事务中。

**尚未恢复**：多层或带损耗 BOM、MRP/MPS、自定义审批、CRM 等其余业务写入、导入导出与附件、门户与多公司隔离、PostgreSQL、授权导入/试用，以及批次/序列号/组合商品/FIFO/FEFO/库区货架成本分支。高级库存参数、单据级折扣、非 CNY、单位换算、赠品及已有活动审批流会拒绝未恢复分支；未知接口返回 501。高级关联和筛选规则仍需逐项核验。

订单普通 PUT 按原程序替换全部明细，未传 `lines` 会清空明细和数量金额；入出库单只修改备注时保留明细。确认后的四类单据拒绝普通编辑和删除。平均库存成本按原程序保留 6 位小数。实测原成本公式以可用库存为加权基础，排除锁定库存；恢复版保留此行为。它与以全部在手数量为基础的成本算法不同。关联单据每个商品仅支持一个订单行；重复商品订单行、已有交付后的取消等未完成对照的分支仍会拒绝。

正式启动可以使用 `-c config.yaml -public-key /secure/public.key -license /data/license.key`。此阶段只支持 SQLite；实际飞牛迁移、已有数据库兼容性和所有业务流程均尚未完成生产验收。请使用独立测试数据库复现。

原程序财务和生产日期要求 RFC3339，裸 YYYY-MM-DD 返回 400。收付款没有 PUT 路由。手工凭证按 draft → posted → approved 执行，posted 可取消但不冲销分录；收付款取消则生成反向凭证。

当前通过 287 条财务/库存及 151 条生产记录，合计 438 条原实例对照回放。财务阶段核对 56 条会计分录/26 张凭证，生产阶段核对 58 条分录/27 张凭证及 7 个科目余额。默认生产领退料和成品入库没有自动会计过账。并发超领、多行缺货回滚及独立进程生产链路已验证。

生产成本保留原行为：领退料使用输入成本，包括 0；成品入库输入成本为 0 时采用工单总成本÷工单数量，正数成本直接使用。流水按计算成本写入，成品单头/明细仍保留输入成本。部分入库累计不得超过工单数量；原程序允许材料未领足时先入库，工单 complete 才检查材料和更新 completed_qty。已确认退料禁止取消/删除，取消后的退料也禁止删除。
